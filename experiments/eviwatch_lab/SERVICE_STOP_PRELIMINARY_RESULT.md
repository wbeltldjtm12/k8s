# 서비스 종료 장애: 예비 반복 결과

> 실행일: 2026-07-25
>
> 상태: 노트북에서 수행한 MVP 예비 결과. 논문 결론으로 사용하지 않는다.

## 실험 조건

```text
정상 8초 → 테스트 HTTP 서비스 강제 종료 10초 → 자동 복구 8초
```

비교 정책:

- `fixed-high`: 1초마다 메트릭, 모든 테스트 서비스 이벤트 보존
- `adaptive`: 정상 시 5초 메트릭과 WARN/ERROR만 보존, health 실패 시 1초 및
  상세 이벤트 보존

서비스 종료 실험에서 CPU 조건은 비활성화했다. 노트북 백그라운드 작업이 CPU
사용률을 바꿀 수 있으므로, 이 실험의 전환 조건은 health 실패만 사용했다.

## 반복 결과

| 정책 | 반복 수 | 평균 관측 산출물 크기 | 평균 장애 구간 샘플 | 평균 전환 지연 |
| --- | ---: | ---: | ---: | ---: |
| `fixed-high` | 3 | 4,501.3 bytes | 10 | 해당 없음 |
| `adaptive` | 3 | 3,070.0 bytes | 9 | 2.026초 |

`adaptive`의 관측 산출물은 `fixed-high`보다 평균 약 **31.8% 작았다.**

세 번의 적응형 실행 모두에서 다음이 기록됐다.

```text
fault_injected
→ health_ok=False / URLError
→ INCIDENT 상태 전환
→ 서비스 복구 뒤 health_ok=True
```

## 해석

이 작은 조건에서는 적응형 정책이 정상 구간의 상세 수집을 줄이면서도, 서비스
중단과 복구 사실을 놓치지 않았다. health 실패를 처음 관찰한 뒤 평균 약 2초에
집중 수집으로 전환한 점은 관측 비용과 탐지 지연의 교환 관계를 보여 준다.

## 한계

- 동일한 노트북 한 대에서 수행했다.
- 서비스 종료 장애 한 종류만 평가했다.
- 반복 수가 3회로 작다.
- 테스트 서비스의 로그량이 매우 작다.
- 실제 저장 예산이 부족한 상태는 아직 만들지 않았다.

다음 실험은 CPU 포화와 안전한 테스트 디렉터리 기반의 저장공간 압박을 추가하고,
관측량이 커지는 조건에서 `Evidence Coverage`를 평가해야 한다.
